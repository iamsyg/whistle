To implement Kafka strictly for the chat message sending flow, here are the exact files that would be created and modified:

---

### 1. New Files to Create

1. **`backend/app/services/kafka_producer.py`**
   * **Role:** Initializes the `AIOKafkaProducer` client on app startup, handles serialization of message JSON payloads, and provides a `send_chat_message(chat_id, message_data)` function that publishes to the `chat-messages` Kafka topic using `chat_id` as the partition key.

2. **`backend/app/services/kafka_consumer.py`**
   * **Role:** Runs a background `AIOKafkaConsumer` task that listens to the `chat-messages` topic, reads messages in batches, and performs batch inserts into the Supabase database (`messages` table).

3. **`backend/app/config/kafka_config.py`**
   * **Role:** Contains Kafka settings (broker URL, topic name `chat-messages`, consumer group ID `chat-db-writer-group`).

---

### 2. Existing Files to Modify

1. **`backend/requirements.txt`**
   * **Changes:** Add `aiokafka==0.12.0` (async Kafka driver for Python/FastAPI).

2. **`backend/.env`**
   * **Changes:** Add `KAFKA_BOOTSTRAP_SERVERS=localhost:9092` and `KAFKA_CHAT_TOPIC=chat-messages`.

3. **`backend/app/main.py`**
   * **Changes:** Add lifespan events (`asynccontextmanager`) to initialize and start `kafka_producer` and `kafka_consumer` when FastAPI starts, and stop them gracefully when FastAPI shuts down.

4. **`backend/app/services/chat_service.py`**
   * **Changes:** In `handle_send_message()`:
     * Instead of synchronously writing to Supabase DB via RPC (`send_message_rpc`), emit the message payload to Kafka via `kafka_producer.send_chat_message(...)`.
     * Keep the real-time WebSocket broadcast so users still receive the live message instantly.

5. **`backend/app/controllers/messages/send_chat_messages.py`** (REST fallback for sending messages)
   * **Changes:** Update the REST send message controller to also publish to the Kafka `chat-messages` topic instead of doing a synchronous direct DB call.
